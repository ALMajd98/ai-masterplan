# 🏛️ AI DEVELOPMENT CONSTITUTION (SEPTEMBER 2026)

## ⚠️ CRITICAL RULES (أولوية قصوى)
- يمنع منعاً باتاً صياغة أي شفرة برمجية لا تتوافق مع هذه المعايير.
- الأمان والأداء مقدمان دائماً على سرعة الإطلاق.

---

## 🔒 ركائز الأمان (Security Principles)

### 1. Zero-Trust Input
- لا تثق أبداً ببيانات العميل (Client-side Data).
- التحقق من نوع البيانات وهيكلها (Schema Validation via Zod) إلزامي في الخادم والباك إند دائماً.

### 2. Secure Sessions
- يمنع تخزين الرموز والـ JWTs في LocalStorage نهائياً.
- الطريقة الوحيدة المقبولة لتداول الجلسات هي ملفات تعريف الارتباط الآمنة (httpOnly, Secure, SameSite=Strict Cookies).

### 3. Database Integrity
- تفعيل Row-Level Security (RLS) في Supabase/PostgreSQL إلزامي لكل جدول يحتوي بيانات مستخدمين.
- يمنع استخدام الاستعلامات النصية المباشرة (SQL Injection Protection). يجب استخدام Parameterized Queries حصراً.

---

## ⚡ ركائز الأداء والتوسع (Performance & Scalability)

### 1. Database Query Optimization
- يمنع استخدام استعلام `SELECT *` في بيئة الإنتاج؛ حدد الأعمدة بدقة.
- تفعيل الفهارس (Indexes) إلزامي لجميع أعمدة الربط والتصفية (WHERE, JOIN, ORDER BY).

### 2. Asynchronous Job Queues
- أي مهمة ثقيلة (إرسال بريد، توليد PDF، معالجة صور، AI Call) يجب ألا تعطل المستخدم.
- نقل المهام الخلفية إلى قوائم المعالجة (BullMQ أو Trigger.dev) إلزامي بالكامل.

### 3. Serverless Edge Caching
- دمج التخزين المؤقت (Redis via Upstash / Vercel KV) للبيانات الساخنة لتقليل الضغط على قاعدة البيانات.

---

## 🛑 محظورات برمجية (FORBIDDEN - NEVER DO)
- لا تقم بتضمين الأسرار والمفاتيح (API Keys) في شفرة المصدر؛ استخدم `.env` دائماً.
- لا ترفع ملفات `.env` إلى مستودع GitHub؛ أضفها فوراً إلى `.gitignore`.
- لا تعرض تفاصيل الخطأ البرمجي للـ Stack Trace للمستخدم النهائي؛ اعرض رسائل عامة وسجل الأخطاء داخلياً في Sentry.
- لا تمنح صلاحيات الإدارة (Admin Privilege) بشكل افتراضي؛ طبق مبدأ الصلاحيات الأقل (Least Privilege).
- لا تثبت أي خادم MCP جديد دون مراجعة مصدره والتحقق من سلامته البرمجية.

---

## ✅ مبادئ معتمدة (MANDATORY - ALWAYS DO)
- تفعيل TypeScript Strict Mode في كل ملفات المشروع.
- معالجة الأخطاء (Error Handling) الشاملة باستخدام try-catch و Error Boundaries.
- تنسيق الشفرة البرمجية التلقائي عبر Prettier و ESLint قبل عمليات الـ Commit.
- تطبيق Conventional Commits للتوثيق الواضح لفروق الكود.
