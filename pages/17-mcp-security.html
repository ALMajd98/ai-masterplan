أمان بروتوكول الـ MCP

Model Context Protocol Security

حماية سلاسل الإمداد البرمجية

يمثل بروتوكول الـ MCP معياراً ثورياً لربط النماذج بالأدوات، ولكن تفعيله بصلاحيات كاملة قد يشكل ثغرة أمنية حرجة. دليل تأمين وإدارة صلاحيات خوادم الـ MCP لمنع تسريب البيانات والوصول غير المصرح للجهاز.

التهديدات الأمنية الأكثر خطورة وكيفية الحد منها

1. هجمات سلاسل الإمداد (Supply Chain)

استيراد أو تشغيل خوادم MCP غير موثوقة من مستودعات GitHub مجهولة قد يؤدي لتنفيذ سكربتات خبيثة تقوم بسحب ملف الأسرار .env ورفعه لخوادم بعيدة.

الحل الصارم: لا تثبت أي خادم MCP إلا بعد التحقق من توثيقه في السجلات المعتمدة (Glama أو Smithery الموثقة بـ DNS)، ومراجعة الكود المصدري لتأكيد النقاء الأمني.
2. الوصول المطلق لنظام الملفات

تفعيل خادم الـ `filesystem` ومنحه وصولاً لكامل قرص النظام C:\ يمنح الـ AI قدرة كاملة على قراءة ملفات تعريف الاتصال الخاصة بـ SSH ومجلدات المستعرض والـ Cache وتمريرها للخارج.

الحل الصارم: تحديد مسارات وصول صارمة وضيقة جداً لـ MCP الملفات وحظر الوصول لقرص النظام الرئيسي.

حظر تصفح الملفات الحساسة عبر ملف `.clineignore` ملف حماية

قم بإنشاء وحفظ هذا الملف في جذر مسار مشاريعك البرمجية لمنع محركات الذكاء الاصطناعي من قراءتها نهائياً:

.clineignore 
# حظر قراءة ملفات البيئة والأسرار
.env
.env.*
*.key
*.pem
secrets/
credentials/

# حظر ملفات الاتصال وصلاحيات الوصول
.aws/
.ssh/
.github/

# استبعاد المجلدات الضخمة وملفات التتبع
node_modules/
.git/
dist/
build/
*.log
*.sqlite
